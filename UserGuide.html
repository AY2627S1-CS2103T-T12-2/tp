TutEasy User Guide

TutEasy is a desktop application for private tutors who manage students, classes, enrolments, and lesson schedules. It is optimized for fast keyboard-driven use through a Command Line Interface (CLI), while its Graphical User Interface (GUI) keeps student and timetable information easy to review.

Quick start

  1. Ensure that Java 25 or later is installed on your computer.
    Mac users: Ensure you have the precise JDK version prescribed here.

  2. Download tuteasy.jar from the latest TutEasy release.

  3. Copy the file to the folder you want to use as the home folder for TutEasy.

  4. Open a terminal, cd to the folder containing the JAR file, and run java -jar tuteasy.jar.
    The TutEasy window should appear in a few seconds with sample student and class data.

  5. Type a command in the command box and press Enter to execute it. For example, type help and press Enter to open the help window.
    Some example commands you can try:

    • list : Shows all students.

    • add n/John Doe p/98765432 e/johnd@example.com a/John street, block 123, #01-01 : Adds a student named John Doe.

    • class add sub/Mathematics cost/40 c/Monday1800-1930 : Adds a weekly Mathematics class.

    • timetable : Opens the read-only weekly timetable.

    • exit : Exits the app.

  6. Refer to the Features section below for details of each command.

Features

Subject searches are described in the subject search guide.

Notes about the command format:

  • Words in UPPER_CASE are the parameters to be supplied by the user.
    For example, in add n/NAME, replace NAME with a value such as John Doe.

  • Items in square brackets are optional.
    For example, n/NAME [t/TAG] can be used as n/John Doe t/friend or as n/John Doe.

  • Items followed by ... can appear zero or more times.
    For example, [t/TAG]... may be omitted, or written as t/friend or t/friend t/family.

  • Parameters can be in any order.
    For example, if the command specifies n/NAME p/PHONE_NUMBER, p/PHONE_NUMBER n/NAME is also acceptable.

  • Extraneous parameters for commands that take no parameters, such as help, list, exit, and clear, are ignored.
    For example, help 123 is interpreted as help.

  • If you are using a PDF version of this document, be careful when copying and pasting commands that span multiple lines as space characters surrounding line-breaks may be omitted when copied over to the application.

Viewing help: help

Opens a window containing the URL of this User Guide. You can also open it from the Help menu or by pressing F1. Use Copy URL in the Help window to copy the link.

Format: help

Adding a student: add

Adds a student to TutEasy, optionally with guardian contacts and one scheduled class.

Format: add n/NAME p/PHONE_NUMBER e/EMAIL a/ADDRESS [t/TAG]... [gn/GUARDIAN_NAME] [gp/GUARDIAN_PHONE] [ge/GUARDIAN_EMAIL] [sub/SUBJECT cost/COST c/SCHEDULE [mode/online|offline] [link/URL] [location/LOCATION] [notes/NOTES]]

Tip: A student can have up to 10 tags. Tags must be unique, contain no more than 30 characters, and use only lowercase letters, numbers, and single hyphens between characters.

Fields Required? What to enter
n/, p/, e/, a/ Yes Student name, phone, email and address. None may be blank.
t/ No Repeat this prefix for multiple tags, up to the tag limit above.
gn/, gp/, ge/ No Any combination of guardian name, phone and email.
sub/, cost/, c/ Together, to enrol in a scheduled class Subject, agreed rate and complete schedule.
mode/, link/, location/, notes/ No Extra details for the scheduled class supplied in the same command.
  • Student names contain letters, digits and spaces, start with a letter or digit, and contain at most 100 characters. Phone numbers contain only digits and have between 3 and 15 digits. Email addresses must follow the email rules below. Addresses may contain at most 500 characters.
  • A name differing from an existing student's name only in capitalization or repeated spaces is rejected as a duplicate, even if its phone or email differs. For example, Alex Yeoh, alex yeoh and Alex Yeoh conflict. Your entered capitalization and spacing are retained for display. This rule also applies when renaming with edit.
  • To include a scheduled class, supply sub/SUBJECT, cost/COST, and c/SCHEDULE together. Subjects start with a letter or digit and may contain letters, digits, spaces, +, -, &, apostrophes, periods, and parentheses. The same subject rule applies to class add, class edit, and subject-based class enrol commands. The agreed rate is non-negative, with at most two decimal places, e.g. 30, 35.50, or 0. Costs cannot exceed 1000000.00. Subject names can contain at most 100 characters. Leading zeroes and an omitted zero before the decimal point are accepted and normalized (e.g. 030 and .5). Supplying only some of these fields rejects the entire command; no student or class is added.
  • Times use the 24-hour range 0000–2359, and the end time must be later than the start time.
  • A weekly schedule uses DAYHHmm-HHmm, for example Monday1800-1930.
  • A one-off schedule uses yyyy-MM-ddTHHmm-HHmm, for example 2026-10-20T1800-1930.
  • If class details are supplied, TutEasy creates the class if necessary and enrols the new student in it.

Examples:

  • add n/John Doe p/98765432 e/johnd@example.com a/John street, block 123, #01-01
  • add n/Betsy Crowe t/friend e/betsycrowe@example.com a/Newgate Prison p/1234567 t/criminal
  • add n/John Davis p/91234567 e/johndavis@gmail.com a/Clementi t/exam-prep sub/Math cost/30 c/Thursday1400-1530
  • add n/Jane Tan p/92345678 e/jane@example.com a/Bishan sub/Math cost/30 c/2026-10-20T1800-1930

Adding guardian and class details to a student

Guardian name (gn/), phone (gp/) and email (ge/) are independent optional fields. You can supply only a phone, only an email, or any combination; none requires the others. Omitted or empty guardian values mean not provided. Leading and trailing spaces around field values are trimmed. Guardian details appear on the student card and persist across restarts. Privacy mode masks them on student cards alongside the student's phone, email and address.

Guardian field rules

Field Rule for a non-empty value Example
gn/ At most 100 characters; starts with a letter or digit; contains only letters, digits, spaces, hyphens and apostrophes (' or ’). gn/Mary-Anne O'Connor
gp/ Between 3 and 15 digits; no spaces, +, brackets or hyphens. gp/98765432
ge/ Uses the email rules below. ge/mary.oconnor@example.com

Email rules, for both students and guardians:

  • An email address may contain at most 254 characters in total.
  • Use local-part@domain. The local part contains letters/digits and may use +, _, . or - between alphanumeric groups; it cannot begin or end with punctuation or contain adjacent punctuation characters.
  • Domain labels are separated by dots. Each starts and ends with a letter/digit, with hyphens allowed between alphanumeric groups. The final label is at least two characters long. Spaces are not allowed.

For example, add n/Bob Tan p/81234567 e/bob@example.com a/Jurong gp/89999999 creates a student with only a guardian phone. Guardian name punctuation is supported independently of the student-name rule.

Class mode, link, location and notes

These fields accompany a complete scheduled class (sub/, cost/ and c/) in the same add command. Each field prefix in this command format can appear once, except t/, which may repeat.

Field Rule
mode/ online or offline, ignoring case. A new class defaults to offline if omitted.
link/ Optional for online classes; must be an absolute HTTP(S) URL with a host. No spaces or embedded username/password; an explicit port must be between 1 and 65535. Offline classes reject a non-empty link.
location/ Optional single-line text, up to 500 characters, without control characters. Available for either mode. Use double quotes when the text contains command prefixes, e.g. location/"Room sub/section 2".
notes/ Optional single-line text, up to 500 characters, without control characters. Available for either mode. Use double quotes when the text contains command prefixes, e.g. notes/"Review sub/section 2".

Notes and locations can appear before other fields. For example, notes/Review gp/99999999 saves the note Review and the guardian phone separately. To include prefix-like text literally, quote the entire value: notes/"Review gn/Mary sub/section 2" gp/99999999. Inside quoted values, use \" for a literal double quote and \\ for a literal backslash. Unclosed quotes or extra text after a closing quote are rejected.

For compatibility, unquoted notes and locations retain sub/, cost/ and c/ as literal text when that class field has already been supplied earlier in the command. For example, sub/Reading cost/20 c/Sunday2100-2200 notes/Review sub/section 2 before class keeps the complete note. Use quotes to make the same text independent of field order; other unquoted prefixes always start separate fields.

For a new class, a link requires explicit mode/online. Supplying a link alone does not change the default mode. An online class may have no link. Examples below assume these student names and lesson times are unused:

add n/Alice Tan p/91234567 e/alice@example.com a/Clementi gn/Mary-Anne O'Connor gp/98765432 ge/mary.oconnor@example.com sub/Algebra cost/30 c/Thursday1000-1130 mode/online link/https://meet.example.com/algebra location/Virtual room notes/Bring worksheet

add n/Dana Tan p/71234567 e/dana@example.com a/Tampines sub/Biology cost/40 c/Saturday1600-1730 mode/offline location/Room 2 notes/Bring calculator

Joining an existing class and inheriting details

TutEasy matches an existing class by its subject (case-insensitive) and complete schedule, including the exact date for a one-off class. Use the existing subject: Math and Mathematics are different subjects. A different class at an overlapping time is rejected.

When a match exists, omitted mode, link, location and notes inherit the class's recorded values, including when the class has no students. Explicit values must agree with those shared values. The exception is an empty class with no recorded extra details: its first student may fill them in. A conflicting command is rejected before the student is added or the shared class is changed.

After the Alice example above, this enrols a second student in the same online Algebra class, inheriting its link, location and notes, at an individual agreed rate of 35:

add n/Ben Tan p/82345678 e/ben@example.com a/Bishan sub/Algebra cost/35 c/Thursday1000-1130

Supplying mode/offline for that same Algebra class would be rejected because its shared mode is online. Omitting mode/ inherits online; supplying link/ with an empty value would conflict with its existing non-empty link. The new student's guardian details and agreed rate are individual. Existing classmates' contacts, rates and payment statuses are unchanged; the new enrolment starts unpaid.

Mode and extra class details appear on student cards, class listings and timetable entries. They remain after the last student unenrols. class delete id/CLASS_ID removes the class and all its enrolments. edit does not accept guardian or class-detail fields; class enrol inherits existing class details. class edit changes subject, default cost or schedule while preserving mode, link, location, notes and individual payment statuses. Use list to leave either read-only view before modifying data.

Adding a class: class add

Creates a class independently of any student. TutEasy assigns a stable class ID such as C001; IDs remain unchanged when a class is edited and are not reused after deletion.

Format: class add sub/SUBJECT cost/COST c/SCHEDULE

Example: class add sub/Physics cost/35 c/Wednesday1800-1930

Classes cannot share the same subject and timing, and overlapping class times are rejected.

Viewing classes: class list

Opens a read-only graphical list showing every class's stable ID, subject, schedule, cost, and stored mode/details.

Format: class list

This command is available from both the student list and timetable. While the class list is open, list, timetable, class list, privacy, help, and exit are available. Use list to return to the student list or timetable to open the timetable.

Editing a class: class edit

Updates a class while retaining its stable ID and enrolments. Supply at least one field to change. Payment statuses and existing students' agreed rates are preserved, and the new shared details appear for every enrolled student. Changing cost/ changes the default rate offered to future enrolments; it does not rewrite existing agreed rates.

Format: class edit id/CLASS_ID [sub/SUBJECT] [cost/COST] [c/SCHEDULE]

Examples:

  • class edit id/C001 cost/40
  • class edit id/C001 sub/Advanced Math c/Tuesday1800-1930

Enrolling students in a class: class enrol

Enrols one or more existing students in a weekly or one-off class. Students are identified by their indexes in the currently displayed student list. Weekly classes recur on their specified weekday; one-off classes occur only on their specified date.

To enrol one student using a stable class ID, use:

class enrol STUDENT_INDEX id/CLASS_ID

Example: class enrol 1 id/C001

To enrol one or more students in an existing class using its subject and complete lesson schedule, omit the cost and provide all student indexes before the prefixes:

class enrol STUDENT_INDEX [STUDENT_INDEX]... sub/SUBJECT c/SCHEDULE

Example: class enrol 1 3 5 sub/Physics c/Wednesday1800-1930

The existing single-student format that supplies the class cost is also supported:

class enrol STUDENT_INDEX sub/SUBJECT cost/COST c/SCHEDULE

The same class can be assigned to multiple students, and each enrolment keeps its own agreed rate. A student cannot be enrolled in the same class more than once. The single-student format records the supplied cost/ as that student's agreed rate. For ID-based and subject-and-timing enrolment, TutEasy uses the class catalogue's current default rate. This also supports classes that currently have no enrolled students.

Batch enrolment validates every index and the target class before changing any student. Repeated or invalid indexes and a missing class cause the command to fail without changing any student. Selected students who are already enrolled are skipped while the remaining students are enrolled. The feedback identifies both groups. If all selected students are already enrolled, no changes are made and an informative message is shown. cost/ cannot be supplied when multiple indexes are used.

Enrolled classes appear below each student's email. Every class group contains a coloured badge with the subject and complete lesson timing, followed by separate Online or Offline and Paid or Unpaid labels. Non-empty meeting links, locations, and notes appear on a wrapped details line below that group. Students enrolled in the same logical class receive the same badge colour, even when their agreed rates or payment statuses differ. When a student has multiple classes, each group appears on its own row and the groups are ordered by schedule, then subject.

A subdued balance badge beside each student's name shows the total agreed rates of that student's unpaid enrolments. Paid enrolments are excluded. The badge remains visible as Balance: 0 when the student has no unpaid enrolments.

Unenrolling a student from a class: class unenrol

Removes one class from one student without affecting other students enrolled in that class.

Format: class unenrol STUDENT_INDEX id/CLASS_ID

Example: class unenrol 1 id/C001

Updating an enrolment's payment status: class payment

Marks one student's enrolment in a weekly or one-off class as paid or unpaid. The student is identified by the index shown in the current student list, while the stable class ID identifies the enrolment.

Format: class payment STUDENT_INDEX id/CLASS_ID status/paid|unpaid

Examples:

  • class payment 1 id/C001 status/paid
  • class payment 1 id/C001 status/unpaid

New and previously saved enrolments default to unpaid. A subdued status label appears immediately after the corresponding coloured class badge, without sharing the badge's background colour. Each class badge and status label stay together on one row, keeping the status associated with the correct class. Updating one student's payment status does not affect other students enrolled in the same class. If the specified student is not enrolled in that class, no data is changed.

Payment status describes the current enrolment as a whole; it is not a payment history for individual weekly sessions or billing months. Correspondingly, the displayed balance is the sum of the current unpaid enrolments rather than a history of accumulated charges.

A successful status change is saved automatically and restored after restarting TutEasy. The balance updates to reflect the new unpaid total. Repeating the current status reports that it is already set. An invalid student index, invalid status, or student who is not enrolled in the specified class receives an error without changing the enrolment.

Deleting a class: class delete

Deletes a class globally by removing it from every enrolled student. Students and their other information are not deleted. The command searches all student records even when the displayed student list is filtered.

Format: class delete id/CLASS_ID

Example: class delete id/C001

Viewing the weekly timetable: timetable

Opens a graphical, read-only timetable containing the complete Sunday-to-Saturday week that includes the current date. Today is highlighted and placed at the top of the scrolling area where possible. Scroll upward to see earlier days in the week and downward to see later days. Every day has a dated heading, even when it has no classes.

Use Previous week and Next week to move exactly seven days at a time. Use Today to recalculate the current date, return to its week, and reload the timetable. Today remains available even while the current week is displayed. The fixed header shows the selected range, for example 18–24 Oct 2026 or 27 Dec 2026 – 2 Jan 2027.

Each class entry shows its start and end time, subject, and all attending students. Classes are ordered by start time, then subject, then end time. Student names within a class are ordered alphabetically.

Weekly classes appear on their matching weekday. One-off classes appear only when their exact date falls within the selected week. Navigating between weeks does not change or save address-book data.

Format: timetable

While the timetable is open, class list, list, privacy, help, and exit are available. class list replaces the timetable with the class list. Use list to return to the student list and re-enable modifying commands. Re-entering timetable after leaving the timetable starts again from the current week rather than the previously viewed week.

Listing all students: list

Shows all students in TutEasy. Pinned students appear before unpinned students.

Format: list

Pinning a student: pin

Pins a student so that they appear above unpinned students in the student list. The pin is saved and remains after TutEasy is restarted.

Format: pin INDEX

  • INDEX refers to the index number shown in the displayed student list.
  • The student must not already be pinned.
  • During a search, only matching students are shown; matching pinned students appear before matching unpinned students.
  • Search relevance and the existing list order are preserved within the pinned and unpinned groups.
  • After a successful command, the displayed list is reordered immediately and its index numbers are refreshed. Use the newly displayed index for the next index-based command.

Example: pin 3

Pinned students display a PINNED badge beside their name and balance.

Unpinning a student: unpin

Unpins a student and returns them to the unpinned section of the student list.

Format: unpin INDEX

  • INDEX refers to the index number shown in the displayed student list.
  • The student must already be pinned.
  • After a successful command, the student moves into the unpinned group immediately. Their relative order within that group follows the existing list order, or the active search ranking when the list is filtered.

Example: unpin 1

The command box suggests the required index after you type pin or unpin.

Editing a student: edit

Edits an existing student.

Format: edit INDEX [n/NAME] [p/PHONE] [e/EMAIL] [a/ADDRESS] [t/TAG]...

  • Edits the student at the specified INDEX. The index refers to the index number shown in the displayed student list. The index must be a positive integer 1, 2, 3, ...
  • At least one of the optional fields must be provided.
  • Existing values will be updated to the input values.
  • When editing tags, all of the student's existing tags are removed; adding tags is not cumulative.
  • To remove all of a student's tags, enter t/ without a tag after it.

Examples:

  • edit 1 p/91234567 e/johndoe@example.com Edits the phone number and email address of the 1st student to be 91234567 and johndoe@example.com respectively.
  • edit 2 n/Betsy Crower t/ Edits the name of the 2nd student to be Betsy Crower and clears all existing tags.

Tagging students: tag

Adds tags to one or more existing students.

Formats:

  • tag INDEX TAG [MORE_TAGS]

  • tag STUDENT_INDEX [MORE_INDEXES] t/TAG

  • Indexes refer to the index numbers shown in the displayed student list.

  • Each tag must be unique for that student.

  • A tag can contain up to 30 characters and use only lowercase letters, numbers, and single hyphens between characters.

  • Spaces separate tags. For example, exam prep adds the two tags exam and prep, while exam-prep adds one tag. Use hyphens when a single tag contains multiple words.

  • A student can have at most 10 tags.

  • The first format adds one or more tags to one student. All supplied tags are validated before the student is updated. If any supplied tag already belongs to that student, or if adding all supplied tags would exceed the 10-tag limit, the command is rejected and no tag is added.

  • The batch format uses t/ to separate one tag from one or more unique student indexes. This also allows numeric tags such as t/2026 without confusing them with student indexes.

  • The batch command validates every index and the tag before updating any student. An invalid or repeated index, or an invalid tag, causes the command to fail without changes.

  • In batch mode, students who already have the tag are skipped. Students who have reached the 10-tag limit are also skipped, while eligible selected students still receive the tag.

  • Batch feedback identifies students who received the tag, already had it, or had reached the tag limit. If no selected student can be updated, no changes are made and the feedback explains why.

Examples:

  • tag 3 exam-prep needs-follow-up
  • tag 1 3 5 t/math-2026

The command box suggests both tag formats after you type tag.

Removing tags from a student: untag

Removes one or more existing tags from a student, or removes all their tags.

Format: untag INDEX TAG [MORE_TAGS] or untag INDEX -all

  • INDEX refers to the index number shown in the displayed student list.
  • Every supplied tag must already belong to the selected student. If any tag is missing, the command is rejected and none of the supplied tags is removed.
  • Use -all by itself after the index to remove every tag. It cannot be combined with tag names or --all.

Examples:

  • untag 2 parent-follow-up
  • untag 5 -all

The command box suggests both removal formats after you type untag.

Locating students by name, tag, subject, or schedule: find

Finds students whose names, tags, subjects, or lesson timings partially match the given search input.

Formats:

  • find KEYWORD [MORE_KEYWORDS]

  • find t/TAG_KEYWORD [MORE_TAG_KEYWORDS]

  • find sub/SUBJECT_KEYWORD [MORE_SUBJECT_KEYWORDS]

  • find c/DAY [TIME_HHmm], find c/TIME_HHmm, or find c/DATE [TIME_HHmm]

  • The search is case-insensitive; for example, hans matches Hans.

  • With no search prefix, the search considers only names. Choose one search category per command.

  • With sub/, any case-insensitive partial keyword may match an enrolled class subject. Multiple keywords are alternatives (OR): find sub/physics chemistry finds students taking either subject, once each. A multi-word query such as find sub/Computer Science also matches Environmental Science through Science. Subject results place pinned matches first and retain original address-book order within each pin group; they do not use relevance scoring. Use one sub/ prefix with non-empty alphanumeric keywords, without name text or t//c/ in the same command. Invalid input keeps the previous results. See the subject-search guide for examples and details.

  • With t/, the search considers only tags. Stored tags use lowercase, but tag search keywords are case-insensitive for input convenience, e.g. find t/PRI matches priority.

  • Name and tag searches use partial matching, e.g. ali matches Alice, and pri matches priority.

  • With c/, search by lesson day, exact date, time, or a supported combination. Days accept full names or prefixes, e.g. Monday or Mon. Exact dates use yyyy-MM-dd. Times use HHmm style from 0000 to 2359, e.g. 1800; shorter fragments such as 18 are accepted for partial matching.

  • An empty search, empty t/ or c/ value, or invalid tag or lesson keyword is rejected with an error. The current displayed results remain unchanged.

  • Name and tag searches return students matching at least one keyword. Matching pinned students are shown before matching unpinned students. Within each group, students with more matching keywords are shown first; ties keep the current list order. Repeating a keyword, even with different letter case, does not increase its relevance score.

  • After a successful find, the command box shows this light-grey hint: Type 'list' to return to the home page.

Examples:

  • find Joh returns John and John Doe
  • find t/fri returns students tagged friends
  • find sub/mAtH returns students taking subjects such as Mathematics; find sub/phys chemistry matches either subject.
  • find c/Monday returns students with Monday lessons
  • find c/1800 returns students with lessons containing 1800
  • find c/Mon 1800 returns students with Monday lessons containing 1800
  • find c/2026-10-20 returns students with a one-off lesson on 20 October 2026
  • find c/2026-10-20 1800 additionally requires the one-off lesson to contain 1800
  • find alex david returns students whose names match alex or david

The command box shows light-grey hints for common find inputs, such as find, the available search formats, the lesson example find c/Monday 1800, and the post-search Type 'list'... hint.

Deleting a student: delete

Deletes the specified student.

Format: delete INDEX

  • Deletes the student at the specified INDEX.
  • The index refers to the index number shown in the displayed student list.
  • The index must be a positive integer 1, 2, 3, ...

Examples:

  • list followed by delete 2 deletes the 2nd student in TutEasy.
  • find Betsy followed by delete 1 deletes the 1st student in the results of the find command.

Clearing all entries: clear

Deletes all student records, classes, and enrolments from TutEasy.

Format: clear

Hiding contact details: privacy

Privacy mode replaces the phone, email, address, and any non-empty guardian contact details on every student card with a fixed seven-asterisk mask, such as Address: *******. While the mode is active, contact details in success feedback from the add and edit commands are masked too. Names, tags, classes, payment information, and pin status remain visible. The underlying contact details are not changed or deleted.

Formats:

  • privacy on masks all displayed contact details immediately.
  • privacy off restores the original contact details immediately.

The mode must be exactly lowercase on or off, with no additional arguments. The privacy command is available from the student list, timetable, and class-list views.

While privacy mode is active, the status bar displays Privacy mode enabled. The selected mode is saved and restored when TutEasy restarts. Privacy mode is disabled by default for existing preference files that do not contain this setting.

The command box suggests both valid modes after you type privacy.

Exiting the program: exit

Exits the program.

Format: exit

Saving the data

TutEasy automatically saves data after every command. You do not need to save manually.

Editing the data file

TutEasy data is saved automatically as a JSON file [JAR file location]/data/addressbook.json. Advanced users are welcome to update data directly by editing that data file.

Caution: If your changes make the data file invalid, TutEasy starts with no student or class data at the next run. The invalid file remains on disk until you run a successful command (TutEasy saves after every successful command). Back up the file before editing it.
Furthermore, certain edits can cause TutEasy to behave in unexpected ways (e.g., if a value entered is outside of the acceptable range). Therefore, edit the data file only if you are confident that you can update it correctly.

FAQ

Q: How do I transfer my data to another computer?
A: Install the app on the other computer and overwrite the data file it creates with the data file from your previous TutEasy home folder.

Q: Why can I not add, edit, or delete data from the timetable or class list?
A: Those views are read-only. Enter list to return to the student list, then run the modifying command.

Q: Why is a weekly class shown in several weeks, while a one-off class appears only once?
A: A weekly schedule recurs on its weekday. A one-off schedule uses an exact date and appears only in the week containing that date.

Q: Does moving between timetable weeks change my saved data?
A: No. Previous week, Next week, and Today only change the timetable projection being displayed.

Known issues

  1. When using multiple screens, if you move the application to a secondary screen, and later switch to using only the primary screen, the GUI will open off-screen. The remedy is to delete the preferences.json file created by the application before running the application again.
  2. If you minimize the Help Window and then run the help command (or use the Help menu, or the keyboard shortcut F1) again, the original Help Window will remain minimized, and no new Help Window will appear. The remedy is to manually restore the minimized Help Window.
