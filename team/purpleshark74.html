Overview

TutEasy is a Java desktop application for private tutors to manage students, guardians, classes, lesson schedules, and payments. It combines a command-line interface with a JavaFX interface and was built collaboratively by our team.

My main responsibility was developing the lesson-scheduling and timetable experience. I worked across the model, storage, logic, UI, testing, and documentation layers to turn recurring and one-off class data into a navigable weekly timetable.

Summary of Contributions

  • Code contributed: tP Code Dashboard and GitHub commits.

Enhancements implemented

  • Graphical timetable view (PR #55):

    • Implemented the timetable command and its end-to-end flow through the logic, model, and JavaFX UI layers.
    • Built the timetable projection model and the panel, day-card, and entry-card UI components. The view groups classes by day, orders them consistently, displays enrolled students, and includes empty days so that the whole week remains visible.
    • Added automated tests across commands, logic, model, and UI components. This was a cross-cutting enhancement that changed 32 files and added dedicated timetable model and UI abstractions rather than placing scheduling logic in the view.

  • Recurring and one-off lesson scheduling (PR #102):

    • Generalised the original weekly-only lesson representation into a shared immutable LessonSchedule abstraction, implemented by weekly LessonTiming and exact-date OneOffLessonSchedule values.
    • Integrated the abstraction with class creation, enrolment, payment, deletion, search, student cards, and the timetable. Added exact-date lesson searches while preserving the existing weekly command format.
    • Extended JSON storage with an explicit schedule type and a migration path that interprets older records as weekly schedules. This kept existing user data loadable without manual conversion.
    • Added focused unit and integration tests for schedule validation, persistence, migration, ordering, class operations, searching, and timetable projection. The completeness of this change required coordinated updates across more than 30 production and test files.

  • Date-backed weekly navigation (PR #105):

    • Added a WeekRange model that normalises any date to a complete Sunday-to-Saturday week and safely handles the boundaries of Java's supported date range.
    • Added Previous week, Next week, and Today controls, dated day headings, selected-range feedback, current-day highlighting, and sensible initial scrolling.
    • Kept the timetable read-only by refreshing it through logic callbacks rather than mutating stored data. Injected clock-aware queries also made date-sensitive behaviour deterministic and testable.
    • Added extensive UI and model tests for navigation, reloading, boundary dates, highlighting, and week layout.

  • Schedule-conflict warnings (PR #69):

    • Warned tutors when adding a student or class would create overlapping lesson times, while still allowing them to decide whether the real-world overlap is acceptable.
    • Covered overlap and non-overlap boundaries with tests. The logic later became date-aware through the shared scheduling model: weekly schedules conflict by weekday, one-off schedules by exact date, and endpoint-only contact is not treated as an overlap.

  • Reliability and validation improvements:

    • Enforced bounded lengths for student and guardian contact fields, with model tests and matching User Guide rules (PR #220).
    • Made address parsing quote-aware so addresses can safely contain text that resembles command prefixes, and added parser regression tests for both add and edit (PR #225).
    • Tightened clear so it rejects unexpected arguments and preserves the user's data on malformed input (PR #237).
    • Fixed truncated timetable notes (PR #158) and corrected class-search matching and its tests (PR #250).
